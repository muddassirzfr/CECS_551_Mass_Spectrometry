# Computational benchmark and execution plan

**Prediction quality remains untested.** These measurements **support preliminary compute-feasibility estimates**; they do not establish structure-level recall, MRR@25, or generalization. All projected total times are estimates and exclude queue wait.

The planned baseline is **CNN + GRU**, a CNN-to-RNN model with a 128-dimensional context and 2 GRU decoder layers. The CNN captures patterns along a fixed mass axis; the recurrent decoder generates SMILES token by token. The primary model retains the sinusoidal peak encoder, spectrum metadata, Transformer encoder, and causal SMILES decoder: attention can combine fragment information across the peak set while conditioning each output token on the spectrum. **Pooled peak embeddings + GRU is auxiliary only**, not the planned baseline or a required training run. Its measurements are preserved but excluded from the CNN + GRU plus Transformer budget. No pooled-GRU timings are transferred to CNN + GRU.

The CNN baseline was benchmarked separately using two input channels (fragment intensities and precursor indicator) on **[0, 4096) m/z** with **0.1-m/z bins** (40,960 bins/channel). Its three Conv1D layers have channels **32, 64, 128**, kernel size **9** and stride **4** each, followed by adaptive average pooling to 16 cells and projection to width 128. Metadata conditions the initial GRU state. It uses the same retained spectral peaks, tokenizer, batch and token cap as the Transformer; input masses outside the grid fail explicitly. The CNN has 771,744 parameters. The supplied PDF specified CNN-to-RNN without these layer/binning details; these are the concrete pilot settings.

The measured Transformer has **4 encoder layers, 4 decoder layers, width 384, 8 attention heads, feed-forward width 1536, dropout 0.1, pre-LayerNorm=True, 512 vocabulary tokens, and 17,614,208 parameters**. The Transformer cap is **129 total encoder positions**: 127 fragment peaks + one precursor + one metadata token. The decoder limit is **160 SMILES tokens including BOS/EOS**. These settings supersede the original PDF's earlier 128-total-input/128-output-token description. Microbatch **32**, accumulation **4**, effective batch **128**; **BF16 autocast** with FP32 model/optimizer state on one **NVIDIA GeForce RTX 3090** (PyTorch 2.7.1+cu118, CUDA 11.8).

Timing procedure: 20 warm-up optimizer updates, then **150 timed complete updates per model**, processing **19,200 spectra** by cycling the **4,096-spectrum** training sample. Each update includes forward loss, backward pass, token-normalized accumulation, gradient clipping, and AdamW; loading/tokenization and device transfer are included. CUDA is synchronized before and after the measured interval. Both models share identity-disjoint partitions, a training-only tokenizer, metadata, and preprocessing. Padding is dynamic: the sampled training targets have median 12, P95 24, and maximum 69 tokens. The full-cap memory stress check is one separate optimizer update; its memory result does not imply full-cap training throughput.

**Full-dataset loading and host-memory feasibility have not been demonstrated.** Cycling 4,096 spectra measures a reused in-memory sample, not a 2,539,608-row Parquet load or sustained full-dataset I/O. The original 2.19 GiB PBS peak host-RAM figure applies only to that small-sample job. It is not a bound or estimate for full-dataset RAM. The current training loader reads the full Parquet file into pandas. A compute-node full-load/RAM profile or a streaming loader is needed before a production run; the extra loading allowance below is an assumption, not evidence of full-data behavior.

Beam timing uses **64 validation spectra**, beam width **25**, inference batch **8**, and no KV cache. Sampling uses **16 reserved spectra**, **100 samples/spectrum**, inference batch **8**, and sample chunk **100**. The short-run weights do not establish prediction quality; remeasure decoding on a validated checkpoint. Training uses 2,242,315 length-filtered spectra × 10 planned epochs. Formula: spectra × epochs / measured spectra/s / 3600, plus measured validation and checkpoint costs, 10% extra loading allowance, and preparation time. Steady-state data loading is already timed.

The **7.16-hour Transformer estimate** is an extrapolation for the stated 10-epoch case, not a completed training run. Training overhead uses teacher-forced loss validation on at most **5,000 spectra per event**, for **97 events** (periodic checks plus epoch ends), extrapolated from 553 measured validation spectra. The validation partition contains **49,951 spectra**. The base plan beam-decodes only **553 validation spectra**, once per planned model, plus Transformer test decoding. Full-partition Transformer beam evaluation is a separate alternative in the table; it is not silently included at every checkpoint.

The capped ranker workload is **2,000 structures × up to 5 spectra = at most 10,000 spectra**; its estimate assumes the cap is reached. It is a subset of the reserved partition. All **247,342 reserved spectra** would instead require approximately **10.01 GPU compute-hours**, excluding **3.39 estimated CPU chemistry-hours** and unmeasured full-holdout ranker fitting. These alternatives are not additive.

GPU compute time and GPU allocation time differ when CPU stages run inline. With the current sequential pipeline, retaining the GPU during subset chemistry and fitting would cost approximately **0.56 allocation-hours**, including the fitting proxy. Full-holdout inline generation alone would cost approximately **13.42 allocation-hours before fitting**. Budget checks conservatively use allocation time for the capped ranker, not GPU compute time alone.

CPU ranker timing uses synthetic labels only; it provides no evidence of recall, ranking quality or validation gain. It times a fit on 70% of synthetic groups plus a refit on all groups, each with 250 boosting trees, 15 leaves and one CPU thread. Decoding speed is conditional on beam width, generated lengths and benchmark weights. Remeasure on the first validated checkpoint.

No ranker or ensemble is committed until the budget is specified and held-out quality supports it. **If the estimated additional cost exceeds the remaining budget, retain the single Transformer.**

The recalculated base plan (**CNN + GRU plus Transformer**, each 10 epochs, and the subset beam evaluation/test pass) requires an estimated **9.93 GPU allocation-hours**. Reserve an additional **2.00 GPU-hours** for extra structure-level evaluation and retries, separate from already estimated validation, checkpointing, and loading costs. Limit extra evaluations and partial retries to this reserve; a full repeated training run requires a revised allocation. Including **0.060 hours** already spent, the minimum total would be **11.99 GPU-hours**. The earlier 9.60-hour base and 11.65-hour minimum budgeted pooled-GRU plus Transformer; those figures do not describe the planned CNN + RNN comparison and are superseded here.

A **proposed 12.00-GPU-hour total plan**, not an approved allocation, would leave **0.01 GPU-hours** after the base plan, prior spend, and reserve. The capped ranker needs approximately **0.56 allocation-hours**; it does not fit, so retain the single Transformer and defer the ranker/ensemble under this proposal.

**Actual full-training GPU allocation: not specified or approved.** The proposed plan cannot be treated as available resources; full training and optional stages remain deferred.

The **confirmed measurement-only allowance is 1.50 hours**. Recorded GPU allocation usage, including the failed startup attempt: **0.060 hours**. The unspent measurement allowance is 1.440 hours; it is not an approved full-training budget.
