Speeds and memory come from the recorded RTX jobs; full-run times are **extrapolations**, not completed training runs. **Prediction quality remains untested.**

The planned comparison is **CNN + RNN (implemented as CNN + GRU) versus one Transformer**. Pooled peak embeddings + GRU is an auxiliary measurement, excluded from the required comparison and base budget.

The Transformer has four encoder and four decoder layers, width 384, eight attention heads, feed-forward width 1536, dropout 0.1, pre-LayerNorm, vocabulary 512, and 17,614,208 parameters. It uses **129 total encoder positions** (127 fragment peaks + precursor + metadata) and **160 SMILES tokens including BOS/EOS**.

The CNN + GRU baseline uses two channels on a 0.1-m/z grid over [0, 4096), or 40,960 bins per channel. Three Conv1D layers have channels 32/64/128, kernel size 9 and stride 4; adaptive pooling produces 16 cells and a width-128 projection conditions a two-layer GRU. Metadata conditions its initial state; it has 771,744 parameters.

Each model used microbatch 32, four-way accumulation (effective batch 128), BF16 autocast and FP32 model/optimizer state. After 20 warm-up optimizer updates, 150 complete updates processed 19,200 spectra by cycling a 4,096-spectrum sample. Timing includes loading/tokenization, transfer, forward/backward passes, gradient clipping and AdamW updates, with CUDA synchronization around the interval. Padding is dynamic; the full-cap memory figure comes from a separate one-update stress check. The table reports peak **allocated** memory, not total device-memory use.

Training projections cover **2,242,315 spectra x 10 epochs** for each required model. They include 97 teacher-forced loss-validation events capped at 5,000 spectra each, checkpoint costs, preparation, and a 10% extra loading allowance. That allowance is an assumption. Cycling 4,096 spectra and observing **2.19 GiB host RAM** in the original job do not demonstrate full-dataset loading speed or RAM feasibility. The current full-Parquet pandas loader still needs a separate memory/I/O profile or replacement with streaming.

Beam timing used 64 validation spectra, inference batch eight, beam width 25, and no KV cache. The base scope evaluates **553 validation spectra per required model**, plus Transformer decoding of **1,213 test spectra**. The full-validation alternative covers 49,951 validation spectra instead. Candidate sampling was timed on 16 reserved spectra with 100 draws per spectrum. Its capped ranker estimate covers **at most 10,000 spectra**, not all 247,342 reserved spectra.

GPU compute time and GPU allocation time differ when CPU processing runs inline. Keeping the GPU allocated through capped-subset chemistry and the CPU fitting proxy would cost about **0.56 allocation-hours**. Full-holdout inline generation would take about **13.42 allocation-hours before fitting**. The CPU ranker measurement uses synthetic labels on one million candidate rows; it provides no ranking-quality evidence.

The CNN + GRU/Transformer base plan is **9.93 GPU allocation-hours**. Adding a two-hour reserve for extra evaluation/partial retries and 0.060 hours already used gives **11.99 hours**. A proposed 12-hour project budget would leave about 0.01 hours outside that reserve, so the capped ranker and ensemble are deferred. The two-hour reserve does not cover a full repeated Transformer run.

**Only a 1.5-hour measurement allowance was confirmed; full training has not been allocated or approved.** Total measured GPU allocation time was **216 seconds**, including the initial failed startup and the separate CNN job. If an optional stage's estimated additional cost exceeds the remaining budget, retain the single Transformer and defer that stage. Any ranker or ensemble also requires held-out MRR@25 improvement.
